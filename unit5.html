1. Basics of Object and Class in C++

Runtime Entity, User-Defined Blueprint, Memory Allocation & The Class vs Object Divide

AKTU Quantum Core • Unit 5 Part 1

1. Basics of Object and Class in C++

1.1 What is an Object?

An Object is a fundamental runtime entity in an object-oriented system that encapsulates both state (data members) and behavior (member functions) into a single cohesive, addressable package.

  • Runtime Existence: While a class exists only at compile time as a blueprint, an object occupies physical RAM at runtime.
  • Instantiation: Creating an object is termed instantiation. When an object is instantiated, the system allocates contiguous physical bytes in memory equal to the cumulative size of its non-static data members (subject to CPU architecture alignment padding).
  • Real-World Representation: Every tangible or conceptual entity in the problem domain (e.g. an ATM Transaction, an Automobile, a Bank Account, or a Student) is modeled directly as a software object.
1.2 What is a Class?

A Class is a user-defined data type (UDT) that serves as the architectural template or prototype from which individual objects are instantiated.

  • Data Abstraction & Encapsulation: A class binds data members and member functions together, hiding internal representation behind public interfaces.
  • User-Defined Type: Once defined, a class behaves identically to fundamental primitive types like int or float; you can create objects, pointers to objects, arrays of objects, and pass them to functions.
  • Class Body Anatomy: Enclosed in curly braces and terminated by a mandatory semicolon (};). Contains data member declarations and member function prototypes or inline bodies.
💡 Real-Life Analogy: The Architectural Blueprint vs. The Physical Villa

An architectural engineer draws a detailed Blueprint on paper for a modern smart villa. The blueprint specifies the number of bedrooms, electrical wiring, plumbing pipe layouts, and the dimensions of every door. That blueprint is the Class: it occupies virtually no physical terrain, you cannot sleep inside it, and you cannot walk through its doors.

When civil contractors build the actual concrete villa in Sector 62, laying bricks and mortar on physical land with a distinct GPS coordinate, that villa is the Object. You can instantiate five villas (Villa v1, v2, v3, v4, v5;) from the exact same single blueprint. Each villa has its own distinct physical location and resident, yet all share the identical architectural structure.

2. Data Members and Member Functions

State vs Behavior, Inline Definitions Inside Class & Out-of-Line Scope Resolution (::)

AKTU Quantum Core • Unit 5 Part 1

2. Data Members and Member Functions

2.1 What are Data Members?

Data Members are variables declared inside a class that represent the state, attributes, or properties of an object. Each object instantiated from the class receives its own independent copy of every non-static data member.

2.2 What are Member Functions?

Member Functions are functions declared inside a class that operate directly upon its data members. Member functions embody the object's behavior and define the legal operations permitted on its state.

2.3 Defining Member Functions: Two Approaches
1
Inside Class Definition (Inline by Default)

When a member function is defined directly inside the class body, the compiler treats it as an implicit request for inlining. Ideal for small, lightweight accessor or mutator routines (1–3 lines).

2
Outside Class Definition via Scope Resolution (::)

The function prototype is declared inside the class, and its full implementation is written outside using the binary Scope Resolution Operator (::):

returnType ClassName::functionName(parameterList) { /* body */ }

Standard practice in production C++ to separate interface (header .h) from implementation (source .cpp).

💡 Real-Life Analogy: The Digital Microwave Oven

Consider a modern Digital Microwave Oven:
- Data Members: Internal state variables: temperatureCelsius, timerSecondsRemaining, powerLevelWatts, and isDoorClosed.
- Member Functions: Operations you trigger through its keypad: startHeating(), cancel(), and setTimer(30).
You cannot reach inside and manually spin the magnetron frequency dials; you press the keypad buttons (member functions) which safely manipulate the internal sensors (data members) under strict rules!

C++ Defining Member Functions Inside vs. Outside Class via Scope Resolution 
#include <iostream>
#include <iomanip>

class BankAccount {
private:
    long accountNumber;
    double balanceAmount;

public:
    // 1. DEFINED INSIDE CLASS: Implicitly inlined by compiler
    double getBalance() const {
        return balanceAmount;
    }

    // Prototypes for functions defined outside
    void initializeAccount(long accNo, double initialDeposit);
    void depositMoney(double amount);
    bool withdrawMoney(double amount);
    void displayAccountSummary() const;
};

// 2. DEFINED OUTSIDE CLASS USING SCOPE RESOLUTION OPERATOR (::)
void BankAccount::initializeAccount(long accNo, double initialDeposit) {
    accountNumber = accNo;
    balanceAmount = (initialDeposit >= 0) ? initialDeposit : 0.0;
}

void BankAccount::depositMoney(double amount) {
    if (amount > 0) {
        balanceAmount += amount;
        std::cout << "Deposited Rs. " << amount << " successfully.\n";
    }
}

bool BankAccount::withdrawMoney(double amount) {
    if (amount > 0 && balanceAmount >= amount) {
        balanceAmount -= amount;
        std::cout << "Withdrew Rs. " << amount << " successfully.\n";
        return true;
    }
    std::cout << "Withdrawal failed: Insufficient funds!\n";
    return false;
}

void BankAccount::displayAccountSummary() const {
    std::cout << "Account [" << accountNumber 
              << "] | Current Balance: Rs. " << balanceAmount << "\n";
}

int main() {
    std::cout << std::fixed << std::setprecision(2);
    std::cout << "=== Bank Account Operations ===\n";

    BankAccount myAcc;
    myAcc.initializeAccount(9876543210L, 25000.0);
    myAcc.displayAccountSummary();

    myAcc.depositMoney(12500.0);
    myAcc.withdrawMoney(8000.0);
    myAcc.displayAccountSummary();

    return 0;
}

3. Private and Public Members

Access Control, Data Hiding, Public Interface vs Private Vault & The Encapsulation Membrane

AKTU Quantum Core • Unit 5 Part 1

3. Private and Public Members: Access Control & Encapsulation

3.1 Principles of Access Control

Access specifiers in C++ define the visibility and accessibility of class members from various program scopes. They are the primary linguistic mechanism for implementing Data Hiding and Encapsulation.

  • Default Access in C++ Class: By default, all members declared inside a class are strictly private (unlike a struct where default access is public).
3.2 Private Members

Members declared under the private: specifier can only be accessed by member functions and friend functions of the same class. External functions and client code (such as main()) cannot read or modify private members directly (e.g. obj.privateVar; // COMPILE ERROR).

Purpose: Protects internal state integrity against corrupted, out-of-range, or unauthorized modifications.

3.3 Public Members

Members declared under the public: specifier are accessible from anywhere in the program wherever the object instance is in scope.

Purpose: Formulates the external interface (contract) through which client code interacts with the class.

💡 Real-Life Analogy: The Bank Teller Counter vs. The Vault

When you walk into a physical retail bank:
- Public Interface: The teller counter window. Any citizen can walk up to the teller window, present a withdrawal slip, or ask for an account statement. The teller window is public:.
- Private Data: The subterranean high-security titanium bank vault storing currency stacks. Customers are legally forbidden from walking directly into the vault to grab cash. The vault is private:.
The public teller function validates your identity, checks your balance, and securely transfers money on your behalf without ever exposing direct access to the vault!

C++ Encapsulation Barrier: Private Data Protected by Public Getters & Setters 
#include <iostream>
#include <string>

class Employee {
private:
    // PRIVATE MEMBERS: Shielded from external tampering
    int employeeId;
    double monthlySalary;

public:
    // PUBLIC INTERFACE: Controlled accessor and mutator methods
    void setEmployeeDetails(int id, double salary) {
        employeeId = id;
        // Business logic validation: salary cannot be negative
        if (salary >= 0.0) {
            monthlySalary = salary;
        } else {
            monthlySalary = 0.0;
            std::cout << "Warning: Negative salary rejected! Set to 0.0\n";
        }
    }

    double getSalary() const {
        return monthlySalary;
    }

    void displayProfile() const {
        std::cout << "Employee [ID: " << employeeId 
                  << " | Monthly Salary: Rs. " << monthlySalary << "]\n";
    }
};

int main() {
    Employee emp;

    // 1. LEGAL: Calling public member functions
    emp.setEmployeeDetails(501, 75000.0);
    emp.displayProfile();

    // 2. ILLEGAL COMPILATION ERRORS: Direct private access rejected
    // emp.monthlySalary = -50000.0; // COMPILE ERROR: 'monthlySalary' is private!
    // std::cout << emp.employeeId;  // COMPILE ERROR: 'employeeId' is private!

    return 0;
}

4. Static Data Members

Shared Class-Level State, Memory Architecture, Out-of-Class Definition & Instance Counting

AKTU Quantum Core • Unit 5 Part 1

4. Static Data Members: Shared Class-Level State

4.1 Meaning of Static Data Members

In standard C++, each object instantiated from a class receives its own separate, distinct copy of all data members. However, when a data member is qualified with the static keyword, only one single copy of that member is created for the entire class, and that single copy is shared collaboratively across all instantiated objects.

4.2 Characteristics & Lifetime Rules
  • Class-Level Scope: It belongs to the class as a whole rather than any individual object instance.
  • Lifetime: Initialized once when the program starts (before main() executes) and persists in the static data segment throughout the entire program lifetime.
  • Default Initialization: Automatically zero-initialized by the runtime system if not explicitly assigned.
  • Declaration vs Definition: Must be declared inside the class declaration, but must be defined and allocated outside the class at file scope (in the .cpp file) using the scope resolution operator:
    int ClassName::staticVarName = initialValue; // Mandatory definition!
💡 Real-Life Analogy: The University Central Student Admission Registry

Imagine an engineering university campus:
- Normal Data Members: Each student carries their own personal Identity Card, backpack, and laptop. If Student A changes their laptop wallpaper, it has zero impact on Student B's laptop. These are instance members.
- Static Data Member: The Total Admitted Students Counter displayed on the central digital notice board in the Registrar's Office. Every time a new student registers at the campus gates, the central counter increments (totalAdmittedStudents++). There is only one shared counter for all 5,000 students on campus!

C++ Static Data Member Declaration, External Definition & Live Instance Counting 
#include <iostream>
#include <string>

class Car {
private:
    std::string chassisNumber;
    std::string modelName;

    // 1. DECLARATION OF STATIC DATA MEMBER (Shared across all Car instances)
    static int totalCarsManufactured;

public:
    Car(std::string chassis, std::string model) 
        : chassisNumber(chassis), modelName(model) {
        // Increments the single shared class-level counter upon creation
        totalCarsManufactured++;
    }

    ~Car() {
        // Decrements when a car object is dismantled/destroyed
        totalCarsManufactured--;
    }

    void printCarDetails() const {
        std::cout << "Car [Chassis: " << chassisNumber 
                  << " | Model: " << modelName 
                  << " | Total Fleet Active: " << totalCarsManufactured << "]\n";
    }
};

// 2. MANDATORY OUT-OF-CLASS DEFINITION: Allocates physical memory in static storage
int Car::totalCarsManufactured = 0;

int main() {
    std::cout << "=== Static Data Member Demonstration ===\n";

    Car c1("VIN-9081", "Sedan Prime");
    c1.printCarDetails();

    Car c2("VIN-9082", "EV SUV Extreme");
    c2.printCarDetails();

    {
        // Temporary inner scope car
        Car c3("VIN-9083", "Track Roadster");
        c3.printCarDetails();
        std::cout << "Exiting local block; c3 will be destructed...\n";
    }

    std::cout << "After c3 destruction:\n";
    c1.printCarDetails();

    return 0;
}

5. Static Member Functions

Class-Level Invocations, this Pointer Absence, Access Restrictions & Diagnostic Operations

AKTU Quantum Core • Unit 5 Part 1

5. Static Member Functions: Class-Level Routines

5.1 Meaning of Static Member Functions

A Static Member Function is a member function qualified with the static keyword that operates at the class level rather than on a specific object instance. It can be invoked directly using the class name without creating any object.

5.2 Three Fundamental Rules of Static Member Functions
1
No Implicit this Pointer

Because a static member function can be invoked without an object instance (ClassName::func()), it does not receive an implicit this pointer.

2
Restricted Member Access

A static member function can ONLY access static data members and call other static member functions directly. It cannot directly access non-static data members (because there is no object instance to select from).

3
Invocation via Scope Resolution

Invoked through the class identifier: ClassName::staticFunction();, although calling through an object (obj.staticFunction();) is syntactically permitted but discouraged as misleading.

💡 Real-Life Analogy: The Bank Interest Rate Inquiry Hotline

Imagine calling a commercial bank's automated phone hotline and pressing 1 for "Current Home Loan Benchmark Interest Rate".
The automated voice immediately states: "The current benchmark rate is 8.25% per annum."
Notice: the automated hotline did not ask you for your personal 16-digit account number or PIN! The benchmark rate is a class-level property applicable to everyone. You do not need to log in to a specific personal account to query the general benchmark rate. That query routine is a Static Member Function!

C++ Static Member Function: Class-Level Invocation without Instantiation 
#include <iostream>

class ServerCluster {
private:
    int serverId;                  // Non-static member (instance specific)
    static int activeNodeCount;     // Static data member
    static double networkBandwidth; // Static data member

public:
    ServerCluster(int id) : serverId(id) {
        activeNodeCount++;
    }

    ~ServerCluster() {
        activeNodeCount--;
    }

    // STATIC MEMBER FUNCTION: Operates at class scope without 'this' pointer
    static void configureGlobalNetwork(double bandwidthGbps) {
        networkBandwidth = bandwidthGbps;
        // serverId = 10; // COMPILE ERROR: Cannot access non-static member without object!
    }

    static void displayClusterDiagnostics() {
        std::cout << "=== Cluster Telemetry ===\n";
        std::cout << "Active Nodes:      " << activeNodeCount << "\n";
        std::cout << "Network Bandwidth: " << networkBandwidth << " Gbps\n";
    }
};

// Allocate memory for static variables
int ServerCluster::activeNodeCount = 0;
double ServerCluster::networkBandwidth = 10.0;

int main() {
    // 1. INVOKING STATIC FUNCTION BEFORE CREATING ANY OBJECT!
    std::cout << "1. Diagnostics before node spin-up:\n";
    ServerCluster::displayClusterDiagnostics();

    // 2. Spin up instances
    ServerCluster node1(101);
    ServerCluster node2(102);
    ServerCluster node3(103);

    // 3. Reconfigure cluster dynamically via class name
    ServerCluster::configureGlobalNetwork(40.0);

    std::cout << "\n2. Diagnostics after node spin-up & reconfiguration:\n";
    ServerCluster::displayClusterDiagnostics();

    return 0;
}

6. Constructors

Automatic State Initialization, Characteristics, Execution Order & The Normal Function Divide

AKTU Quantum Core • Unit 5 Part 2

6. Constructors: Automatic Object Initialization

6.1 Meaning of a Constructor

A Constructor is a specialized member function of a class whose primary responsibility is to initialize the state of an object automatically at the moment of its physical creation. It ensures that no object ever enters program execution in an uninitialized, garbage-filled state.

6.2 Essential Architectural Characteristics of Constructors
  • Name Invariance: Must bear the exact same identifier as the enclosing class (e.g. class Matrix has constructor Matrix()).
  • Absence of Return Type: Has no return type whatsoever — not even void. Attempting to write void Matrix() turns it into a regular member function, not a constructor.
  • Automatic Invocation: Automatically triggered by the C++ runtime system whenever an object instance is created on the stack (Matrix m;) or heap (new Matrix()). It cannot be called explicitly like a normal function (e.g. m.Matrix(); // ILLEGAL).
  • Public Visibility: Normally declared in the public: section so that external scopes can instantiate objects (private constructors are reserved for specialized design patterns like Singleton).
  • Cannot be Virtual: In standard C++, constructors cannot be virtual because an object's concrete type must be known at compile time to allocate memory, and the virtual table pointer (vptr) is initialized inside the constructor body.
💡 Real-Life Analogy: The Factory Reset Sequence of a New Smartphone

When you purchase a brand-new smartphone and power it on for the very first time, you do not find random corrupted fragments from previous owners in its storage. The device automatically runs its out-of-box initialization sequence (the Constructor): it sets the system language to default English, formats the solid-state storage, zeroes the battery health monitor, and initializes the operating system variables to a clean, reliable baseline before you ever touch a single app!

7. Types of Constructors

Default, Parameterized, Copy Constructors, Deep vs Shallow Copy & The Infinite Recursion Trap

AKTU Quantum Core • Unit 5 Part 2

7. Types of Constructors: Default, Parameterized & Copy

7.1 The Three Core Types of Constructors

In C++, constructors can be overloaded to provide multiple flexible mechanisms for initializing objects. The AKTU curriculum rigorously tests three canonical forms:

1
Default Constructor

A constructor that accepts no parameters (or where all parameters have default values). If no constructor is written by the programmer, the C++ compiler automatically synthesizes a trivial default constructor. However, if any parameterized constructor is defined, the compiler-generated default constructor is suppressed!

Complex() : real(0.0), imag(0.0) {}
2
Parameterized Constructor

A constructor that accepts one or more arguments to initialize an object with specific customized data values at creation time. Best implemented using modern Member Initializer Lists for optimal performance.

Complex(double r, double i) : real(r), imag(i) {}
3
Copy Constructor

A constructor that initializes a new object by copying data members from an existing object of the same class:

ClassName(const ClassName& other); // Mandatory const reference parameter!

Why Passed by Reference? If passed by value (ClassName(ClassName other)), passing the argument would itself require calling the copy constructor, triggering an infinite recursive loop and stack overflow!

7.2 Shallow Copy vs. Deep Copy Hazard

The default compiler-generated copy constructor performs a Shallow Copy (member-wise bitwise copy). If a class owns raw heap pointers (int* ptr = new int[10];), shallow copying duplicates only the pointer address, causing two objects to point to the exact same heap memory. When both objects destruct, the second destructor triggers a fatal Double-Free Crash! A user-defined Deep Copy Constructor must allocate distinct heap memory and copy the actual underlying data.

💡 Real-Life Analogy: Three Ways to Buy a Laptop

1. Default Constructor: You walk into an electronics store and say: "Give me the standard laptop off the shelf." It comes with base factory defaults (8GB RAM, 256GB SSD, Silver color).
2. Parameterized Constructor: You customize your order online: "Give me a laptop with 32GB RAM, 2TB SSD, in Space Grey." You pass explicit custom arguments at checkout.
3. Copy Constructor: You love your colleague's perfectly configured development laptop. You hand a blank laptop to IT and say: "Clone all installed tools, configs, and environments from my colleague's machine into my new machine." A fresh, independent duplicate is born!

C++ Exhaustive Demonstration: Default, Parameterized & Deep Copy Constructors 
#include <iostream>
#include <cstring>

class CustomString {
private:
    char* buffer;
    int length;

public:
    // 1. DEFAULT CONSTRUCTOR
    CustomString() {
        length = 0;
        buffer = new char[1];
        buffer[0] = '\0';
        std::cout << "[Default Constructor] Empty string initialized.\n";
    }

    // 2. PARAMETERIZED CONSTRUCTOR
    CustomString(const char* text) {
        length = std::strlen(text);
        buffer = new char[length + 1];
        std::strcpy(buffer, text);
        std::cout << "[Parameterized Constructor] Created: '" << buffer << "'\n";
    }

    // 3. DEEP COPY CONSTRUCTOR (Must pass by reference: const CustomString&)
    CustomString(const CustomString& other) {
        length = other.length;
        // Allocate completely SEPARATE heap memory buffer (Deep Copy)
        buffer = new char[length + 1];
        std::strcpy(buffer, other.buffer);
        std::cout << "[Deep Copy Constructor] Safely cloned: '" << buffer << "'\n";
    }

    // Destructor cleans up allocated heap buffer
    ~CustomString() {
        delete[] buffer;
    }

    void display() const {
        std::cout << "Content: \"" << buffer << "\" | Address: " 
                  << static_cast<void*>(buffer) << "\n";
    }
};

8. Destructors: Deterministic Teardown & RAII

8.1 Meaning of a Destructor

A Destructor is a special member function that is automatically invoked when an object's lifetime ends. Its primary architectural duty is to release resources acquired by the object during its lifetime (e.g. freeing heap memory allocated via new, closing open file descriptors, closing database sockets, or unlocking mutexes).

8.2 Essential Rules & Characteristics of Destructors
  • Tilde (~) Prefix: Must share the exact class name preceded by a tilde symbol (e.g., ~FileStream()).
  • No Arguments & No Return Type: Destructors cannot accept any parameters and cannot return any value.
  • Zero Overloading: Because it accepts no arguments, a class can have only ONE destructor. Overloading a destructor is impossible.
  • Automatic Invocation Scenarios:
    1. When a local stack-allocated object exits its enclosing scope (e.g. at the closing brace }).
    2. When dynamically allocated heap objects are explicitly deallocated using delete or delete[].
    3. When global or static objects are destroyed upon program exit.
  • Reverse Order of Construction: Local stack objects are destructed in strict LIFO (Last-In, First-Out) order — the object created last is destructed first.
💡 Real-Life Analogy: The Hotel Room Checkout Protocol

When you check into a hotel room (Constructor), you are handed the room keycard, towels are placed on the racks, and your minibar account is initialized.
When your stay ends and you checkout (Destructor), the hotel protocol triggers automatically: you return the keycard, room utilities are powered down, and your security deposit is reconciled.
If hotel guests walked away without a checkout protocol (a missing destructor), rooms would stay occupied, keys would leak, and the hotel would run out of resources! In C++, destructors guarantee that every object leaves no orphaned memory behind.

9. Operator Overloading: Syntactic Elegance for Custom Types

9.1 Meaning and Purpose of Operator Overloading

Operator Overloading is a form of compile-time polymorphism in C++ that allows standard built-in operators (such as +, -, *, ++, ==, <<) to be given customized definitions when applied to user-defined class objects.

Why Overload Operators? Rather than forcing awkward, verbose function calls like c3 = c1.addComplex(c2);, operator overloading enables intuitive, mathematically natural expressions:

Complex c3 = c1 + c2; // Natural, clean mathematical syntax
9.2 General Operator Syntax
returnType operator op(argumentList) { /* body */ }

where operator is a C++ keyword followed immediately by the operator symbol being overloaded (e.g. operator+, operator++).

9.3 Member Function vs. Friend Function Approach
  • Member Function: The left-hand operand is implicitly passed as the invoking object (*this). A unary operator takes 0 explicit arguments; a binary operator takes 1 explicit argument (the right-hand operand).
  • Friend Function: Independent function without a this pointer. A unary operator takes 1 explicit argument; a binary operator takes 2 explicit arguments (left and right operands). Mandatory when the left operand is not a class object (e.g. cout << obj requires a friend operator function).
💡 Real-Life Analogy: The Universal "+" Sign

Consider the + symbol in human communication:
- If applied to two bank currency amounts: Rs. 500 + Rs. 200 = Rs. 700 (numerical addition).
- If applied to two postal addresses: "Flat 402" + "Gaur City" = "Flat 402, Gaur City" (string concatenation).
- If applied to two vectors in physics: Vector A + Vector B = Resultant Vector (parallelogram law addition).
Humans naturally understand that the operational mechanics of + depend entirely on the types of objects being joined. Operator overloading gives C++ user-defined classes this exact semantic elegance!

C++ Overloading Unary Increment (++) & Binary Addition (+) on Complex Numbers 
#include <iostream>

class Complex {
private:
    double real;
    double imag;

public:
    Complex(double r = 0.0, double i = 0.0) : real(r), imag(i) {}

    // 1. UNARY OPERATOR OVERLOAD (++ prefix) as Member Function
    // Takes 0 explicit arguments because '*this' is the operand
    Complex& operator++() {
        ++real;
        ++imag;
        return *this; // Return modified object reference
    }

    // 2. BINARY OPERATOR OVERLOAD (+) as Member Function
    // Takes 1 explicit argument: the Right-Hand Side (rhs) operand
    Complex operator+(const Complex& rhs) const {
        return Complex(real + rhs.real, imag + rhs.imag);
    }

    // 3. FRIEND STREAM EXTRACTION OPERATOR (<<)
    // Requires 2 arguments because left operand is std::ostream, NOT Complex!
    friend std::ostream& operator<<(std::ostream& out, const Complex& c) {
        out << c.real << " + " << c.imag << "i";
        return out;
    }
};

int main() {
    Complex c1(3.5, 2.5);
    Complex c2(1.5, 4.5);

    std::cout << "=== Operator Overloading Demonstration ===\n";
    std::cout << "c1: " << c1 << "\n";
    std::cout << "c2: " << c2 << "\n";

    // Binary Addition: Resolves to c1.operator+(c2)
    Complex sum = c1 + c2;
    std::cout << "c1 + c2 = " << sum << "\n";

    // Unary Increment: Resolves to c1.operator++()
    ++c1;
    std::cout << "After ++c1: " << c1 << "\n";

    return 0;
}

10. Rules of Operator Overloading

10. Rules of Operator Overloading: Constraints & Non-Overloadable Operators

10.1 The Canonical Rules of Operator Overloading

The C++ compiler enforces strict safety boundaries to prevent programmers from corrupting language grammar:

  1. Existing Operators Only: Only existing C++ operators can be overloaded. You cannot invent new operators (e.g. ** for exponentiation or $$ are illegal).
  2. Must Involve at Least One User-Defined Type: You cannot alter the meaning of operators on primitive types (e.g. you cannot redefine 1 + 2 to equal 5). At least one operand must be a class, struct, or enum.
  3. Precedence and Associativity are Preserved: Overloading an operator does NOT alter its binding priority or evaluation direction. * will always have higher precedence than + regardless of user definition.
  4. Arity Cannot Change: Unary operators remain unary; binary operators remain binary. You cannot turn division / into a unary operator.
  5. Default Arguments Disallowed: Overloaded operator functions cannot have default argument values.
10.2 The Non-Overloadable Operators in C++

The AKTU syllabus specifically asks which operators CANNOT be overloaded under any circumstances:

.* Pointer-to-Member Dereference Operator Core language reflection mechanism that must remain compile-time invariant.
:: Scope Resolution Operator Directs compiler lookup across symbol tables; not an expression operator.

typeid RTTI Type Identification Operator Core runtime type inquiry mechanism guaranteed by C++ ABI.
10.3 Operators That MUST Be Member Functions

The following four operators cannot be overloaded as friend functions; they MUST be non-static member functions of the class:

  • = (Assignment Operator)
  • [] (Subscript Operator)
  • () (Function Call Operator)
  • -> (Member Access via Pointer Operator)

11. Type Conversion in C++: Basic & Class Types

11.1 Taxonomy of Type Conversions in C++

In pure procedural C, type conversion occurs between primitive numeric types (e.g. float to int). In C++, because classes define brand-new types, type conversions span three distinct architectural dimensions:

1
Basic Type to Class Type

Converting a primitive type (e.g. int or double) into a custom class object. Accomplished via a Single-Argument Conversion Constructor:

Time t = 120; // 120 minutes converted to Time object (2 hrs, 0 mins)
2
Class Type to Basic Type

Converting a custom class object into a primitive type (e.g. Complex to double magnitude). Accomplished via a Conversion Operator Function (Casting Operator):

operator double() const { return std::sqrt(real*real + imag*imag); }

Rules: Has no return type in header, accepts no arguments, must be a member function.

3
Class Type to Another Class Type

Converting an object of ClassSource into an object of ClassDestination (e.g. converting PolarCoords to CartesianCoords). Can be implemented either as a conversion constructor in the destination class, or as a casting operator in the source class.

💡 Real-Life Analogy: Currency Exchange & Units Conversion

- Basic to Class Type: You hand a raw integer number 5000 to an international bank teller, and they hand you back a structured BankDraft Object (with security seals, watermarks, account tokens). A raw number became a rich object.
- Class to Basic Type: You hand an international traveler's check object to the cashier, and they hand you back raw cash banknotes (double totalCash). A rich object collapsed into a primitive value!

12. Concept of Inheritance: Hierarchical Code Reusability

12.1 Meaning and Purpose of Inheritance

13. Modes of Inheritance: The 3x3 Visibility Matrix

13.1 What is an Inheritance Mode?

When deriving a class in C++, an access specifier (public, protected, or private) is placed immediately before the base class name. This access specifier determines the maximum visibility level of inherited members inside the derived class and to external client code.

17. Virtual Base Class: Resolving the Diamond Problem

17.1 The Diamond Problem in Multipath Inheritance

In Hybrid / Multipath inheritance, a derived class (D) inherits from two intermediate classes (B and C), both of which share a common ancestor base class (A):

     [A]
    /   \
  [B]    [C]
    \   /
     [D]

The Fatal Bug: Without virtual base classes, class D receives two duplicate copies of class A's data members (one through path A → B → D, and a second through A → C → D). This leads to two critical problems:

  1. Wasted RAM: Redundant duplication of all base class variables in every object of D.
  2. Fatal Ambiguity: Accessing a member of A like d.val; causes a compilation error: "member 'val' is ambiguous" because the compiler cannot deduce whether B::val or C::val was intended!
17.2 The Solution: Virtual Base Class

By qualifying the intermediate inheritance declarations with the virtual keyword:

class B : virtual public A { /* ... */ };
class C : virtual public A { /* ... */ };

we instruct the C++ compiler to maintain only ONE shared instance of class A in the memory layout of the most-derived class D, completely eliminating redundancy and ambiguity!

19. Pointers in C++: Memory Addresses, Indirection & Allocation

19.1 What is a Pointer?

A pointer in C++ is a specialized variable that stores the physical or virtual memory address of another variable rather than storing a direct data value. Pointers provide the underlying infrastructure for dynamic memory management, efficient array handling, complex data structures (trees, graphs, linked lists), and dynamic polymorphic dispatch.

  • Address-of Operator (&): A unary operator that extracts the hexadecimal memory address of an existing variable.
  • Dereference / Indirection Operator (*): A unary operator that accesses, reads, or modifies the actual value residing at the address stored inside the pointer.
19.2 Syntax and Memory Layout
int count = 42;               // Regular variable storing value 42

C++ provides dynamic memory allocation from the system Heap at runtime:

  • new: Allocates memory on the heap and returns the address of the newly allocated storage.
  • delete: Releases single-object memory back to the heap to prevent memory leaks.
  • delete[]: Releases dynamically allocated array memory back to the operating system.

21.1 Meaning and Mechanics of the this Pointer

In C++, this is an implicit, hidden pointer passed automatically as the first hidden parameter to every non-static member function. It holds the hexadecimal memory address of the specific object instance for which the member function was invoked.

22. Virtual Functions: Runtime Polymorphism & Dynamic Dispatch

22.1 What is a Virtual Function?

A Virtual Function is a member function declared within a Base Class using the keyword virtual and re-defined (overridden) in one or more Derived Classes.

When a function is declared virtual, C++ implements Late Binding (Dynamic Binding): when that function is invoked through a Base Class pointer or reference, C++ determines at runtime which version of the function to execute based on the actual type of the object pointed to, rather than the static type of the pointer!

22.2 Internal Mechanics: The vtable and vptr Architecture

How does C++ achieve runtime dynamic dispatch under the hood with near-zero overhead? It utilizes two compiler-generated structures:

  • Virtual Table (vtable): A static array of function pointers created by the compiler for every class that contains at least one virtual function. Each entry in the vtable points to the most-derived implementation of the virtual function for that class.
  • Virtual Table Pointer (vptr): A hidden pointer automatically inserted by the compiler into every object instance of a class with virtual functions. vptr points directly to that class's vtable.

When executing bPtr->draw(), the processor:
1. Follows bPtr to the object in memory.
2. Reads the object's hidden vptr.
3. Indexes into the corresponding vtable to retrieve the function address.
4. Jumps to and executes that specific function!

  • The radio protocol is identical (Base interface), but the duty schedule board (vtable) dynamically dispatches the right specialist at the exact moment of arrival!

23. Pure Virtual Functions & Abstract Classes: Interface Contracts

23.1 What is a Pure Virtual Function?

A Pure Virtual Function (or abstract function) is a virtual function declared inside a base class that has no implementation within that base class. It is denoted by the pure specifier syntax = 0:

virtual void functionName() = 0;  // Pure virtual function declaration

A pure virtual function acts as an uncompromisable architectural contract: it commands all non-abstract derived classes to provide their own concrete implementation of this function.

23.2 What is an Abstract Class?

An Abstract Class in C++ is any class that contains at least one pure virtual function.

  • Instantiation Prohibited: You CANNOT instantiate an object of an abstract class (e.g. AbstractClass obj; will trigger a compilation error).
  • Pointers and References Permitted: You CAN declare pointers and references of abstract class type (e.g. AbstractClass* ptr; is 100% valid and represents the cornerstone of polymorphic interface architecture).
  • Concrete Classes: A derived class that overrides and implements ALL pure virtual functions from its abstract base class is called a Concrete Class, and can be instantiated freely.
  • Pure Abstract Class (Interface): A class containing ONLY pure virtual functions and no data members is equivalent to a Java/C# Interface.
💡 Real-Life Analogy: The ISO Wall Socket Specification

Consider the international regulatory standards committee that designs the specification for electrical wall sockets:

  • The standard document defines: "Any electrical appliance plug must have a ground pin, line pin, and neutral pin, and must implement connectPower()."
  • You cannot plug the regulatory paper document (Abstract Class) into the wall to power your laptop; it is merely an architectural specification.
  • A manufacturer creates a physical Indian 3-pin plug or a British Type-G plug (Concrete Derived Class). That physical plug strictly satisfies every specification clause and can be plugged in and instantiated!
